##  2. <a name='Whatisalinkedlist'></a>What is a linked list?

[⬆️ Back to Top](#linked-lists-general-overview)

* A linear data structure that stores a sequence of elements.
* While an array is stored in contiguous memory, linked lists are not. Instead, each element lives somewhere in memory and holds a **pointer** (or reference) to the next element, giving the structure its "linked" quality.
* Typically represented by a reference to its **head**, which is the first node in the list. 
    * From the head, every other node can b e reached by following the chain of pointers.

##  3. <a name='Linkedlistnode'></a>Linked list node

[⬆️ Back to Top](#linked-lists-general-overview)

* **node** - the fundamental building block of a linked list.
* Contains two things:
    * **data** - the value being stored (can be a number, string, object, anything)
    * **pointer** - a reference to the next node

##  4. <a name='Typesoflinkedlists'></a>Types of linked lists

[⬆️ Back to Top](#linked-lists-general-overview)

* **Singly linked list** - each node only points to the *next* node. Traversal is unidirectional (forward-only).
* **Doubly linked list** - each node points to both the *next* and the *previous* nodes. Traversal is bi-directional.
* **Circular linked list** - The tail node points back to the head instead of `null`, forming a loop. Can be singly or doubly linked.

##  5. <a name='LinkedListsvs.Arrays'></a>Linked Lists vs. Arrays

[⬆️ Back to Top](#linked-lists-general-overview)

Arrays and linked lists are both linear sequences, but they differ fundamentally in how they work.

| **Feature**                   | Array                                          | Linked List                                         |
|-------------------------------|------------------------------------------------|-----------------------------------------------------|
| **Memory layout**             | Contiguous (elements are side-by-side)         | Non-contiguous (scattered in memory)                |
| **Access by index**           | `O(1)` — direct via index math                 | `O(n)` — must traverse from the head                |
| **Insert/delete at head**     | `O(n)` — must shift elements                   | `O(1)` — just rewire a pointer                      |
| **Insert/delete at tail**     | `O(1)` amortized (with dynamic arrays)         | `O(n)` singly, `O(1)` doubly (with tail pointer)    |
| **Insert/delete in middle**   | `O(n)`                                         | `O(n)` to find + `O(1)` to rewire                   |
| **Memory overhead**           | Low — just the data                            | Higher — each node stores extra pointer(s)          |
| **Size flexibility**          | Fixed (static) or costly to resize (dynamic)   | Naturally dynamic — grows/shrinks easily            |

* Arrays are great when you need fast access by index.
* Linked lists are great when you need fast insertions and deletions, especially at the head, and when the size of your data changes frequently.

###  5.1. <a name='BehaviorinMemory'></a>Behavior in Memory

[⬆️ Back to Top](#linked-lists-general-overview)

####  5.1.1. <a name='Arrays:'></a>Arrays:

* System allocates a *single contiguous block* of memory.
* Index-based access works in `O(1)` because the address of any element can be computed as:
    ```
    address = base_address + (index * element_size)
    ```

####  5.1.2. <a name='Linkedlists:'></a>Linked lists:

- Each node is allocated independently, wherever the memory allocator finds space.
- Nodes may be spread across completely different regions of memory.
- Only way to get from one node to the next is by following the pointer stored in each node.
- This is why random access is `O(n)` - you must traverse the list to get to your target node.
- This means linked lists have a **memory overhead** per node - each node must store not just its data, but also one or two pointers (typically 8 bytes each on a 64-bit system).
